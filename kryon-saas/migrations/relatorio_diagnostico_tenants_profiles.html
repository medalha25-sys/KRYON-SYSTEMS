Diagnóstico de Foreign Key: profiles.tenant_id vs tenants vs organizations

Incidente: ERROR: 23503 (profiles_tenant_id_fkey): Key (tenant_id) is not present in table "tenants"

1. Causa Raiz do Erro de Foreign Key (23503)

🔴 O Que Ocorreu:

1. O trigger handle_new_organization_owner() do V5.1 tentou executar: UPDATE public.profiles SET tenant_id = NEW.id WHERE id = NEW.owner_id.

2. No entanto, a coluna public.profiles.tenant_id possui uma foreign key legada (profiles_tenant_id_fkey) apontando para a tabela legada public.tenants(id) em vez de public.organizations(id).

3. Como a nova organização foi criada em public.organizations e não existe em public.tenants, o PostgreSQL barrou a operação.

2. Bateria de 8 Consultas de Diagnóstico (Somente Leitura)

Para mapear com 100% de exatidão o estado das tabelas e chaves estrangeiras sem modificar nenhum registro, foi elaborado o script consolidado diagnostico_tenants_organizations_profiles.sql.

-- 1. FK de profiles: SELECT tc.constraint_name, kcu.column_name, ccu.table_name AS foreign_table, ccu.column_name AS foreign_column FROM information_schema.table_constraints tc JOIN information_schema.key_column_usage kcu ON tc.constraint_name = kcu.constraint_name JOIN information_schema.constraint_column_usage ccu ON ccu.constraint_name = tc.constraint_name WHERE tc.table_name = 'profiles' AND tc.constraint_type = 'FOREIGN KEY'; -- 2. Schema da tabela/view tenants: SELECT column_name, data_type, is_nullable FROM information_schema.columns WHERE table_name = 'tenants'; -- 3. Contagem de registros: SELECT COUNT(*) FROM public.tenants; SELECT COUNT(*) FROM public.organizations; SELECT COUNT(*), COUNT(*) FILTER (WHERE tenant_id IS NOT NULL) FROM public.profiles; -- 4. Definição do trigger handle_new_organization_owner e tipo da relação tenants (r = BASE TABLE, v = VIEW): SELECT pg_get_functiondef(oid) FROM pg_proc WHERE proname = 'handle_new_organization_owner'; SELECT relname, relkind FROM pg_class WHERE relname = 'tenants';
