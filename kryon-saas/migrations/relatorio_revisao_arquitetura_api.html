🔍 ARQUITETURA DE TESTE AJUSTADA (ZERO HARDCODE)

Revisão e Correção da Arquitetura do Teste de Isolamento RLS

Escopo: Separação entre Setup de Fixtures e Execução via Supabase REST API com Asserts Reais

1. Resolução dos Dois Apontamentos Técnicos (ISSUE-01 e ISSUE-02)

✔ ISSUE-01 (API Real vs Simulação SQL): Removida a simulação via set_config em SQL. A execução dos 8 cenários passa a ser realizada 100% via PostgREST / Supabase SDK em Node.js com Bearer JWTs oficiais de USER_A e USER_B.

✔ ISSUE-02 (Evidências Dinâmicas vs Hardcoded): Eliminada qualquer tabela com status estático. Todo status PASS ou FAIL é derivado dinamicamente em runtime através de asserts estritos de HTTP Status, contagem de registros e tratamento de erros.

2. Critérios de Validação Dinâmica dos 8 Cenários
# Cenário Identidade Chamada API Condição Exata para PASS

02 Leitura Própria Org B USER_B (JWT Real) GET /services?tenant_id=eq.OrgB status == 200 && data.length == 1 && id == servB
