🛡️ PROPOSTA TÉCNICA DE CORREÇÃO RLS

Relatório Técnico: Correção de Recursão 42P17 via Função Booleana

Módulo: Kryon Lava Rápido & Fundação Central | Banco: Sistemas Kryon (pgpobxvkojawrstadrel.supabase.co) | Status: 🛑 Não Executado

1. Diagnóstico da Causa Raiz da Auto-Recursão

🔴 Onde e Por Que a Recursão Ocorre:

Na tabela public.organization_members, a policy original "Membros podem ver outros membros..." executava uma subconsulta que lia a própria tabela organization_members. Quando qualquer policy (em services, customers, appointments ou na própria organization_members) abria uma subconsulta em organization_members, o PostgreSQL disparava a checagem RLS em cascata infinita, gerando o erro 42P17.

2. Função Auxiliar Booleana com Hardening (Sem Enumeração)

🟢 Assinatura: public.is_user_member_of_organization(target_organization_id UUID)

• SECURITY DEFINER: Executa a checagem com privilégios do owner, ignorando o RLS interno de organization_members e quebrando o ciclo de recursão.

• STABLE: Permite cache de resultado no planejador de query do PostgreSQL.

• SET search_path = public, pg_temp: Blindagem contra path hijacking.

• Retorno Booleano Puro: Retorna estritamente TRUE ou FALSE para o tenant consultado, sem listar outros IDs e sem permitir enumeração de dados.

CREATE OR REPLACE FUNCTION public.is_user_member_of_organization(target_organization_id UUID) RETURNS BOOLEAN AS $$ SELECT EXISTS ( SELECT 1 FROM public.organization_members WHERE organization_id = target_organization_id AND user_id = auth.uid() AND status = 'active' ); $$ LANGUAGE sql SECURITY DEFINER STABLE SET search_path = public, pg_temp;
3. Controle Rigoroso de Privilégios (GRANT / REVOKE)

🔒 Controle de Acesso da Função:

• REVOKE ALL ON FUNCTION public.is_user_member_of_organization(UUID) FROM PUBLIC, anon;

• GRANT EXECUTE ON FUNCTION public.is_user_member_of_organization(UUID) TO authenticated;

Impedindo acesso por visitantes não logados e liberando apenas para a role authenticated.
