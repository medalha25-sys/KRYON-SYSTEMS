2. Diagnóstico Técnico na Avaliação de Policies (PostgreSQL 42P17)

⚠️ Detecção de Auto-Recursão na Policy de organization_members

Durante a chamada via API PostgREST sob a role authenticated, o PostgreSQL retornou o erro 42P17 (infinite recursion detected in policy for relation "organization_members").

Causa Raiz: A policy prévia de fundação "Membros podem ver outros membros da mesma organização" em organization_members executa um SELECT organization_id FROM public.organization_members. Ao avaliar a própria tabela dentro da policy da mesma tabela, o PostgreSQL entra em loop recursivo.

4. Solução Técnica Padrão Supabase (Eliminação da Recursão)

✔ Criação de Função SECURITY DEFINER Helper

Para eliminar a recursão no PostgreSQL sem abrir mão de 100% da segurança RLS, a prática recomendada pelo Supabase é encapsular a busca de organizações em uma função SECURITY DEFINER ou simplificar a policy:

CREATE OR REPLACE FUNCTION public.get_user_organization_ids() RETURNS SETOF UUID AS $$ SELECT organization_id FROM public.organization_members WHERE user_id = auth.uid() AND status = 'active'; $$ LANGUAGE sql SECURITY DEFINER STABLE SET search_path = public, pg_temp; -- Policy em organization_members sem recursão: CREATE POLICY "Membros visualizam seus registros de membros" ON public.organization_members FOR SELECT USING (user_id = auth.uid() OR organization_id IN (SELECT public.get_user_organization_ids()));
